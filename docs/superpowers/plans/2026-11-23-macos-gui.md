# streamprobe for Mac Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native SwiftUI Mac app (layout B: verdict sidebar + Live/Details/Events tabs) for spot-checking a radio stream, driven by the existing `streamprobe` binary through a new opt-in `--live-json` mode.

**Architecture:** Rust gets one new module (`src/live.rs`) that serialises state as newline-delimited JSON, wired into `main.rs` behind `--live-json`. A Swift package in `macos/` has a testable library (`StreamprobeKit`: message decoding, process runner, session state, highlight mapping, findings-doc parser) and a thin SwiftUI executable (`StreamprobeApp`). A shell script assembles `dist/Streamprobe.app` with `streamprobe` as a helper binary and ad-hoc signs it.

**Tech Stack:** Rust 1.88+ (serde_json, clap), Swift 6 / SwiftUI / Observation, Swift Testing, SwiftPM, macOS 14+.

**Spec:** `docs/superpowers/specs/2026-11-23-macos-gui-design.md`

## Global Constraints

- No diagnostic logic in Swift; Swift only displays what streamprobe reports. The highlight table (Task 5) is display-only.
- CLI behaviour and output without `--live-json` must be byte-for-byte unchanged; existing flags, reports and exit codes untouched.
- `--live-json` conflicts with `--json` and `--no-ui`; stdout carries only one compact JSON object per line; human text goes to stderr.
- `make lint` and `make test` must pass after every Rust task (rustfmt, clippy `-D warnings`).
- Every Swift build/test command runs with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`. Never run `xcode-select -s` or anything needing sudo.
- Swift: language mode 6, `platforms: [.macOS(.v14)]`.
- Server-controlled strings (titles, headers, ICY fields, issuer, ffprobe output, finding and event messages) are shown only via `Text(verbatim:)`, never `LocalizedStringKey`/Markdown/`AttributedString(markdown:)`, with no link detection.
- Stop = `SIGINT`; if the process hasn't exited 3 s later, `SIGKILL`.
- App bundle: `dist/Streamprobe.app`, bundle id `uk.co.hippynet.streamprobe`, helper at `Contents/Helpers/streamprobe`, ad-hoc signed (helper first, then app). `STREAMPROBE_BIN` env var overrides the helper path.
- Work on branch `macos-gui`. Commit messages end with the session's attribution lines.

## Review Focus

1. **stdout arriving in arbitrary chunks** (a line split across reads, several lines in one read, a trailing line without `\n` at exit, an unknown `type` from a newer CLI) → every complete line is decoded once, unknown types ignored. Pinned in Task 3 (`LineSplitter` + `unknownTypeIsIgnored`).
2. **Blank, whitespace-padded or scheme-less URLs** → Check disabled for blank; URL trimmed; no scheme passed through (the CLI adds `http://`). Pinned in Task 4 (`CheckRequestTests`).
3. **The process ending without a `final` line** (killed, crashed, SIGINT while connecting, or `error` line such as ffmpeg missing) → a specific end state, never a blank window. Pinned in Task 4 (`sessionEndStates`).
4. **Very long checks (hours)** → app memory bounded: the event list mirrors the CLI's cap (5000; keep first 100 + most recent). Pinned in Task 4 (`eventsAreBounded`).
5. **Server text containing Markdown or links** (`**x**`, `[a](http://…)`) → rendered literally. Pinned in Task 6 by a grep gate over `macos/Sources/StreamprobeApp`.

### Task 1: `src/live.rs`, the line builders

**Files:**
- Create: `src/live.rs`
- Modify: `src/main.rs:20-28` (add `mod live;`)
- Test: unit tests inside `src/live.rs`

**Interfaces:**
- Consumes: `report::json_report(&State, f64, &str) -> Value`, `findings::findings(&State, f64, bool)`, `findings::overall`, `ui::text_report(&State, f64, Pal, &str)`, `State` fields listed below.
- Produces (all `pub`, all return `serde_json::Value` objects with a `"type"` key):
  - `start_line(url: &str) -> Value` → `{"type":"start","version":VERSION,"url":url}`
  - `live_line(st: &State, now: f64, seen_events: u64) -> Value`
  - `report_line(st: &State, now: f64) -> Value` → `{"type":"report","report":json_report(st, now, "in progress")}`
  - `final_line(st: &State, now: f64, stop_reason: &str, exit_code: i32) -> Value` → `{"type":"final","report":<json_report>,"json_text":<to_string_pretty of that report>,"text":<text_report with Pal{on:false}>,"exit_code":n}`
  - `error_line(code: &str, message: &str) -> Value` → `{"type":"error","code":…,"message":…}`
  - `emit(v: &Value)`: `serde_json::to_string(v)` + `\n` to stdout, then flush.

`live_line` shape (field names are fixed here; Swift decodes exactly these):

```
{"type":"live","elapsed_s":f1,"phase":"live"|"down","stream_url":final_url,
 "levels":{"rms_l","rms_r","peak_l","peak_r"} | null,          // null unless st.cur is Some and last_block within 2 s (dashboard's `fresh`)
 "loudness":{"momentary_lufs","short_term_lufs","integrated_lufs","lra_lu","true_peak_dbtp"},
 "stereo":{"state":Class::code()|null,"correlation","side_db"},  // from st.cur when fresh
 "quality":{"bandwidth_hz","samples_over_0dbfs","samples_at_full_scale","max_peak_dbfs","decode_errors"},
 "delivery":{"realtime_ratio","input_kbps"|null (null when mode_direct),"listener_buffer_s","underruns","stalls","disconnects"},
 "now_playing":{"title","since_s","previous"},                  // previous = second-to-last of st.titles
 "result":overall(findings(st, now, false)),
 "findings":[{"level","code","message"}],                        // findings(st, now, FALSE): matches the dashboard
 "events":[{"t","offset_s","level","code","message"}],           // only events newer than seen_events
 "events_total":st.events_total}
```

Numbers use `jnum(_, 1)` (null for missing / -inf), `phase` uses the dashboard's `alive` rule (`ui.rs` `render`). New events: `unseen = (st.events_total - seen_events).min(st.events.len())`, take the last `unseen` of `st.events` (same rule as the `--no-ui` loop in `main.rs`).
